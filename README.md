## 導入

1. Forge 1.20.1（47.4.10以上）を導入します。
2. `re-academycraft-forge-1.20.1-1.5.2.jar`を、クライアントの`mods`フォルダーへ入れます。マルチプレイではサーバーにも入れます。
   - 公式の導入用JARは、CurseForge（<https://www.curseforge.com/minecraft/mc-mods/re-academycraft>、Project ID `1735500`）だけで配布します。
   - GitHubのreleaseには、アドオンの開発者向けのSDK（下の「アドオンの開発（SDK）」）を添付します。SDKのJARは導入用ではありません。
   - 導入用JARのSHA-256: `c79475fd843d1e0a85d1a3cdef0cba9469e140fdef5833147e80db161125e088`
3. 更新の前に、ワールドと設定をバックアップしてください。
   - 1.5.2では、未元装甲を廃止しました。習得していた場合、更新後は装甲の軽減がなくなります（習得と熟練度の記録はワールドに残りますが、技能としては表示されず、使えません）。`academy-common.toml`の`skill.dark_matter_armor`の項目は、読み込んだときにForgeがファイルから外します。
   - 1.5.0で、未元物質の能力の保存と新しい設定を足しました。1.4.1以前から更新するとき、セーブデータに無い新しい設定は、既定の値で始まります。
   - アドオンを入れると、アドオンの技能の設定が、アドオンごとのファイル`config/academy-addon-<名前空間>.toml`にできます。
   - 1.0.0のセーブを初めて読み込んだときは、1.1.0と同じく、最大CPを新しい方式へ1回だけ移します（1.0.0標準式と一致しないカスタム最大CPは保持します）。設定ファイルは、新しい項目を足す前に`academy-common.toml.before-capacity-v2.bak`へ写します。
   - 1.5.2で開いたワールドを、1.5.1以前へ戻すことは保証しません。戻すときは、更新の前に取ったバックアップを使ってください。
   - マルチプレイでは、サーバーと参加する全員のクライアントを1.5.2にそろえてください。
   - 以前の試験版で遊んだワールドは、開いたときに能力データなどを新しい保存の形へ移します。移した後のワールドは、以前の試験版では正しく読めません。
   - クライアントとサーバーは同じバージョンを使用してください。互換性のない通信プロトコルは接続時に拒否されます。
   - 1.5.2で通信プロトコルを変えたので、1.5.1以前のサーバー・クライアントとは接続できません。
   - アドオンを使うときは、サーバーと参加する全員のクライアントに同じアドオンを入れてください。能力の登録が違うと、違う能力の名前を示して接続を断ります。
4. 他のAcademyCraftや、以前の試験版のJAR（`academycraft-forge-1.20.1-…`）と同時に入れないでください。mod IDが同じ`academy`です。

- 能力の5系統:
  - 電撃使い（Electromaster）
  - 原子崩し（Meltdowner）
  - テレポート（Teleporter）
  - ベクトル操作（Vector Manipulation）
  - 未元物質（Dark Matter。1.5.0で追加）

## 能力の決まり（1.5.2）

- **パッシブ／アクティブ**: 身体強化・ジェット・エンジン・ライト・シールド・エレクトロン・ミサイル・フラッシング・風の翼・ベクトル偏向・ベクトル反射・白翼自動防御・未元光線・天界発現は、熟練度100%で、能力設定からパッシブに切り替えられます。パッシブの技能はスキルスロットから外れます。能力使用モードの間、防御の技能と切り替え型の技能は自動で起動します。風の翼とジェット・エンジンは自動では飛ばず、白翼飛行と同じく、空中でジャンプを長押しすると離陸します。パッシブで起動している技能が多いほど、過負荷の回復が遅くなります。
- **過負荷とCP**: 過負荷の回復の待ちは、過負荷が増えたときだけ始まります。待ちの長さは習得した最上位のコースで決まり、熟練度では短くなりません。過負荷のロック中は、どの技能も自分では新しく始められません。ただし、回復の待ちが終わって過負荷が減り始めると、パッシブにしている技能と、ロックした瞬間に飛んでいた飛行が、順に自動で戻ります（戻った技能は、ロックが解けるまで維持だけです）。CPの回復の待ちは、技能でCPを使ったときだけ始まり、維持費や防御の支払いでは始まりません。
- **飛行の技能**（白翼飛行・風の翼・ジェット・エンジン）: 白翼飛行とジェット・エンジンは離陸ごとにCPと過負荷を払います。風の翼は離陸の費用の代わりに無料の溜めがあります。飛んでいる間は回復するCPの一部を払います。横に動く・速く飛ぶほど、費用が上がります。
- **防御の技能**（ベクトル偏向・ベクトル反射・ライト・シールド・白翼自動防御、ジェット・エンジンの前からの攻撃の軽減）: オンにしているだけでは費用がかかりません。防御が働いた攻撃1回ごとに、防いだダメージに応じたCPと過負荷を払います（ジェット・エンジンの前からの攻撃の軽減は「回数の分 ＋ 防いだダメージ × 係数」のCP）。CPが足りないか、CPセーフティに掛かる1回は防ぎません。
- **ベクトル操作の解析度**: ベクトル偏向・ベクトル反射の守る力は、ダメージの分類ごとの解析度で決まります。偏向か反射を使っている間に攻撃を受けると、解析度が上がります。バニラの物理のダメージは、最初から100%です。解析度は、能力設定と、データ端末のアプリ「ベクトル解析」で見られます。能力使用モード中、『すべて』は全分類、『選んだ物だけ』はチェックした分類を表示します。初期設定は『選んだ物だけ』で選択は空です。
- **電撃使いと原子崩しの干渉**: 電撃使いと原子崩しは、能力使用モード中で過負荷ロックや能力干渉器の干渉がない間、通常の落雷と相手系統の一部の攻撃を無効にします。天界発現の落雷と、変更履歴の例外表にある技能のダメージは通ります。
- **ダメージの種類**: 技能のダメージは系統ごとに種類が分かれます。本体の技能ダメージには共通タグと系統タグが付きます。接触・刺突など当たり方を区別する種類には、対応する当たり方のタグも付きます（`#academy:skill_damage`・`#academy:ability/<系統>`・`#academy:hit/<当たり方>`）。データパックやほかのMODから、どの系統の能力のダメージかを見分けられます。
- 値と細かい決まりは、1.5.2の変更履歴を見てください。

## サーバーと設定

- 能力の判定・CPと過負荷・技能の結果・機械の動作は、**サーバーが決めます**。クライアントは操作を送り、結果を表示します。

| ファイル | 内容 |
| --- | --- |
| `config/academy-common.toml` | ゲームの規則（ダメージの倍率、CP・過負荷の回復、技能の有効・無効、地形の破壊など）。 |
| `config/academy_client.properties`、`config/academy_hud.properties`、`config/academy_media_player.properties` | クライアントだけの設定、HUDの配置、メディアプレイヤーの音量など。 |

- `academy-common.toml`は**ゲームのインスタンス全体で1つ**です。シングルプレイでは、そのインスタンスのすべてのワールドに効きます。
- 専用サーバーでは、**サーバーの**`academy-common.toml`の値が使われます。サーバーへ参加したクライアントの`academy-common.toml`は、そのサーバーでは何も決めません（表示に必要な規則はサーバーから送られます）。
- 以前の試験版で作ったワールドには、ワールドごとの`serverconfig/academy-server.toml`が残っている場合があります。
  - このファイルはもう読まれず、値は**自動では移りません**。必要な値は`config/academy-common.toml`へ手で写してください。
  - サーバーの起動時に、古いファイルと違っている項目と移し方をログへ出します。古いファイルは消しません。
- 1.5.2で既定値を変えた設定（`ability.storm_wing.thrust_overload_per_second`、風の翼の推進の過負荷）は、1.5.1の既定値`[3.0, 1.0]`のままなら、読み込んだときに1.5.2の既定値`[0.0, 0.0]`（推進では過負荷がかからない）へ書き換えます。値が`[2.0, 0.0]`（1.5.2の開発中の既定値）のときも、同じく書き換えます。そのほかの値に変えていた場合はそのまま残し、書き換えた項目はログに出します。
- 1.5.2から使わなくなった項目（ベクトル偏向・ベクトル反射・ライト・シールド・ジェット・エンジン・風の翼の`ability.toggle_upkeep`、風の翼の滞空の項目、`ability.capacity.idle_recovery_share`）は、ファイルに残りますが効果はありません。一覧を最初の読み込みのときにログへ出します。
- 解析度の画面への表示の設定は、クライアントだけの設定として`config/academy_client.properties`に保存します。

## 既知の問題・注意

- **既存のチャンク**: 鉱石と虚相位液体の湖は、新しく生成されるチャンクにだけ出ます（上の「既存のワールド」）。
- **ほかのMODとの組み合わせ**: Oculus・Embeddium・BSLの組み合わせで主な表示を確かめました。ほかのシェーダーパックや描画を変えるMODとの組み合わせは確認していません。BSLでは、一部の縁取りなどがシェーダーなしのときと少し違って見えます。表示がおかしいときは、それらを外して試してください。
- **エレクトロン・ミサイルの攻撃対象の既定**: 1.3.0から、既定では敵対Mob（と自分を狙っているMob）だけを撃ちます。1.2.0は、種類で選ばずに、射程内で最も近い生き物を撃っていました（プレイヤーは、PvPなどの設定が許す場合だけ）。能力設定の画面か、`/academy missile target neutral on`・`/academy missile target friendly on`で、1.2.0に近い撃ち方に戻せます。防具立ては、どの設定でも撃ちません。
- **能力設定の画面**: エレクトロン・ミサイルの照準と攻撃対象、ライト・シールドのモードを変えられます。値はサーバーが持ち、チャットのコマンド（`/academy missile`・`/academy shield`）と同じ値です。操作設定の「能力設定を開く」のキーの既定は、割り当てなしです。
- **アドオン（公開API）は実験的です**: 1.5.2の後の版で、APIの名前や形が変わることがあります。アドオンがMinecraftを直接変える処理（本体のAPIを通さない攻撃・ブロックの変更など）は、Re:AcademyCraftでは止められません。アドオンを外しても、そのカテゴリ・技能・プリセットの枠は休眠のまま残り、戻せば元どおり使えます。アドオンが描く光線（メルトダウナーの見た目）と、シェーダーや描画を変えるMODとの組み合わせは確認していません。
- **ウィンドウ・画面から戻った直後のキー**: ウィンドウから離れて戻った直後や、画面・データ端末を閉じた直後は、押したままだった技能のキー・移動キー（風の翼の推進、フラッシングの方向）を、一度離して押し直すまで新しい操作として扱いません。戻った後の最初の1回の押下が効かないことがあります。そのときは、もう一度押してください。
- **水中の光線の表示**: 一部の能力エフェクト（メルトダウナー、エレクトロン・ボム、スキャッター・ボム、エレクトロン・ミサイル、超電磁砲の光線と弧、レイ・バラージュなど）の描画順序を変えました。水面の下の光線が消える問題の改善を目的とした変更で、期待どおりの見え方になるかは実画面で確認していません。光線の奥にある半透明のブロック（水面・色付きガラス・氷など）や、粒子・雲・天気が、光線の上に重なって見えることがあります。シェーダーや描画を変えるMODとの組み合わせでの見え方は、確認していません。
- **未元物質・人体生成**: 他のMODが死亡の処理を独自に行う場合（HPを直接0にする、死亡の処理を上書きするなど）には働かないことがあります。
- **未元物質の翼と頭上の輪の光り方**: シェーダーパックの使用中は、能力設定の「翼の発光」が100%のとき、自動で90%として描きます（保存された設定は100%のままです）。100%の光り方では、シェーダーパックのブルームで翼（刺突の翼と自動防御の羽の球を含む）が真っ白に光り、形が見えなくなるためです。それでも光りすぎるときは、「翼の発光」（0〜100%）をさらに下げてください。
- **原作との見た目の違い**: Electron Missileの光線の始点、Thunder Boltの範囲の弧など、一部に原作と違う見た目が残っています。
- **素材**: 原作由来の素材の一部は、作者・再配布の条件が確認できていません（下の「クレジット・ライセンス・権利」）。
- **翻訳**: 英語・簡体字中国語の文章は、母語話者による校正をしていません。気づいた点はIssueで教えてください。

## ソースからのビルド

- 必要なもの: JDK 17。初回はGradle・Minecraft Forge・Mojangのライブラリを取得するためにインターネット接続が必要です。
- Gradle wrapper（Gradle 8.8）を同梱しています。

```sh
./gradlew clean build
```

- 導入用のJARは`build/libs/re-academycraft-forge-1.20.1-1.5.2.jar`です（`reobfJar`で再難読化したもの）。
- 同じ場所の`-sources.jar`は導入用ではありません。
- sourceと文書はUTF-8です。Javaのコンパイルとリソースの処理にUTF-8を指定しているので、WindowsでもLinuxでも、OSの既定の文字コードに依存せずにビルドできます。
- JARはファイルの時刻と順序を固定して作ります。Temurin 17.0.20.1では、同じsourceからの2回のビルドが同じバイトになりました。JDKのベンダーや版が違うと、同じsourceでもバイトが変わることがあります。
- CurseForgeで配布する1.5.2のJARは、このブランチの1.5.2のtagと同じファイル（改行はLF）からビルドしたものです。
- SDKのJARは、`./gradlew apiJar apiSourcesJar apiJavadocJar`で作ります（APIのJavadocは、Eclipse AdoptiumのJDK 17で作ります）。サンプルのアドオンの作り方は`samples/academy-api-example/README.md`にあります。
- 一部のデータ（レシピ・戦利品・ワールド生成・素材のモデルなど）は`tools/generate_*.py`（Python 3）で生成し、生成結果をリポジトリに入れています。生成スクリプトはリポジトリのルートで実行します。

## アドオンの開発（SDK）

- 1.4.0から、第三者のアドオンが能力のカテゴリと技能を足せる公開API（**実験的**）があります。1.4.1で、反射の状態などの読み取りと、4系統にまたがる対応済みの演出を足しました。1.4.0向けのアドオンの互換は確かめていません。1.5.0ではAPIを変えていません。1.5.1では、演出API（`ExternalPresentation`）を版3にして未元物質の演出を足し、本体の技能`academy:dark_matter_beetle`の発動方式を`INSTANT`から`HELD`に変えました（公開APIの版`AcademyApi.VERSION`は2のまま）。1.5.2では、公開APIのバージョン`AcademyApi.VERSION`を3にして、`api.mc.AbilityStatus`（プレイヤーごとの今の発動方式と、ベクトル操作の解析度の参照）と、`CategoryDefinition`の5番目の値`randomAcquire`を足しました。本体の技能のダメージの種類のIDも変わりました（種類のIDで判定していたアドオンは、タグで判定してください）。開発者向けの手引きは`API_GUIDE_JA.md`です。
- SDK（APIのJAR・API sources・Javadoc・サンプルのアドオン・手引き・ハッシュの一覧）は、GitHubのrelease（<https://github.com/PinChan4273/Re-AcademyCraft/releases/tag/1.20.1-v1.5.2>）のファイルとして無料で配布します。CurseForgeは本体だけです。
- SDKのライセンスは本体と同じGPLv3です（`LICENSE`・`NOTICE.md`・原作のREADMEの追加の文言）。APIのクラスはアドオンへ入れず、実行には本体が要ります。
- 配布するバイナリに対応するソースは、このブランチの1.5.2のtagにあります。API sourcesのJARは参照用です。
